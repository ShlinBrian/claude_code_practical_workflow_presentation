MSSQL → PostgreSQL Migration — Four-Arm Workflow Experiment

Same task (migrate a Java download backend MSSQL→PostgreSQL, verify per-endpoint against golden MSSQL), four execution disciplines. Read-only extraction from branches naive (A), superpowers-end-to-end (B), superpowers-goal (C1), superpowers-workflow (C2). Repo clcom-product-downloader-migrate · report generated 2026-06-23.

Read this first — the verifier is not what the experiment design assumed. The brief frames success as a per-endpoint, per-row A/B comparison against a golden MSSQL response. In the committed artifacts that oracle was only partially realised:
  • Only Arm B committed a row-level data-parity artifact (326/326 table row-counts, live PG vs live MSSQL) and a real captured per-endpoint run (newman-report.json).
  • A, C1, C2 verify with an HTTP-2xx / no-DB-error smoke check, not a golden-response row diff.
  • Arm A committed no verifier artifact at all — its Postman collection contains zero assertions; "47/47" is a number typed into an HTML report.
So a higher endpoint pass-rate does not mean stronger verification. This is recorded factually throughout; see Provenance.

2 · Code-quality deep-dive centerpiece

Scored against the rubric: correctness robustness, tests, structure & readability, review trail. Every score is backed by a real excerpt with file path + line. The thesis under test: disciplined workflow makes quality stop depending on luck.

The headline finding on quality. The SQL-conversion craft scored 5/5 on every arm — even naive A genuinely handled TOP/ISNULL/GETUTCDATE/refcursor/citext/cross-DB. The arms did not diverge on conversion correctness; they diverged on everything that surrounds it: verification rigor, commit hygiene, and reproducibility. Tests scored A=1, C2=1, C1=2, B=4. No arm produced a committed code-review score (review trail = NOT FOUND on all four).

Quality here was a coin-flip that landed well on craft and badly on discipline.
