完成定義

先給我一份 outline:
三家的關鍵差異、建議聚焦的 USP 方向、背後的判斷邏輯

不要直接寫完整報告 — 先給一版框架,我審過後再進下一步

框架用 markdown,每段搭配 3 到 4 個 bullet points

How — 過程

  • 手把手規定它每一步怎麼操作
  • 「打開 Excel,在 A1 輸入…」
  • = 實習生模式,該砍掉的
VS

What — 成品規格

  • 成品長什麼樣,本來就該由你來定
  • markdown、3-4 bullets = 規格
  • = 完成定義,該留下的

你拿掉的是 how,不是 what

最值錢的一條:「先給框架,不要直接寫完整報告」

有 checkpoint

先給一版框架→你審方向,不對直接調→再往下展開高效

沒有 checkpoint

直接寫完 30 頁報告→才發現方向不對→整份重來

改動成本太高,也浪費 token

完成定義不是官僚流程,是仁慈
